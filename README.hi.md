## यह क्या है?

Escape the Valley एक ओरेगन ट्रेल-शैली का सर्वाइवल गेम है जो आपके टर्मिनल में चलता है। यात्रियों के एक समूह को प्रक्रियात्मक रूप से उत्पन्न जंगल में ले जाएं। घटनाओं, खतरों और कठिन विकल्पों का सामना करते हुए भोजन, पानी, गाड़ी की स्थिति और मनोबल का प्रबंधन करें।

एक वैकल्पिक एआई गेम मास्टर (Ollama द्वारा संचालित) तीन अलग-अलग कहानी कहने वाली आवाजों के साथ आपकी यात्रा का वर्णन करता है। एक वैकल्पिक XRPL Testnet लेजर बैकपैक आपकी आपूर्ति में होने वाले बदलावों को ऑन-चेन रसीदों के रूप में ट्रैक करता है - यह प्रमाण कि आपने जीवित रहे, या यह प्रमाण कि आपने कोशिश की।

## नया क्या है

**1.3.3** — किसी फोर्क पर सेव को फिर से लोड करने पर अब आप शिविर में वापस आ जाते हैं, जहाँ आपने छोड़ा था, इसलिए फिर से लोड किए गए गेम में वही गेम चलता है जैसे आपने कभी बंद नहीं किया था (#41)। अब हर मृत्यु का कारण सहित, उसकी रिपोर्ट की जाती है, जिसमें आराम करते समय, शिकार करते समय, मरम्मत करते समय, कम राशन पर या किसी घटना के कारण होने वाली मौतें शामिल हैं; ये सभी ट्रेल लेजर, आँकड़ों और गेम मास्टर की स्मृति तक पहुँचते हैं (#42)।

**1.3.2** — प्रति-`event_id` कूलडाउन (`N=4`) यह सुनिश्चित करता है कि एक ही घटना का ढांचा लगातार या लगभग लगातार टर्न में दोहराया न जाए (#21; 1.3.1 → 1.3.2 घटना के चयन को उस समय के बाद स्थानांतरित करता है जब दोहराव होता, इसलिए 1.3.1 में सहेजा गया गेम 1.3.2 में अपग्रेड करने के बाद अलग तरह से जारी रहता है क्योंकि घटना के चयन में बदलाव होता है। एक ही संस्करण में, एक ही बीज और एक ही विकल्प एक ही गेम चलाते हैं)। जीएम-ऑफ सीएलआई परिणाम पैनल एक बार में डिफ़ॉल्ट सारांश प्रस्तुत करता है (#20), विकल्प संकेत में दोहराए जाने वाले दोहरे विराम चिह्न हटा दिए जाते हैं, और `1 mile remaining.` एकवचन व्याकरण का उपयोग करता है। दूषित `.trail/secrets.json` फ़ाइलों को फिर से लिखने से पहले अलग कर दिया जाता है (#31.7)। `THIRD_PARTY_NOTICES*.txt` और `trail licenses` आउटपुट को सभी प्लेटफ़ॉर्म पर एलएफ में सामान्यीकृत किया जाता है, और सीआई डाउनलोड किए गए पायथन-बिल्ड-स्टैंडअलोन संग्रह के विरुद्ध वेंडर्ड लाइसेंस की अखंडता को सत्यापित करता है (#31.1, #31.2, #31.3, #31.5)।

**1.3.1** — सीएलआई गेम (`trail new` / `trail continue`) अब मेमोरी कार्ड और मृत्यु के कारण की तरह ही जानकारी प्रदर्शित करते हैं, जैसा कि टीयूआई (`trail stats`, ट्रेल लेजर मृत्यु दिवस और जीएम मेमोरी ब्रीफ दोनों मोड में काम करते हैं) में होता है। टीयूआई एबंडन कार्गो वास्तव में छोड़ी गई कार्गो की रिपोर्ट करता है। फोर्क रूट संकेत अब गाड़ी के रखरखाव या एस्केप-वाल्व कूलडाउन के एक टर्न को बर्बाद नहीं करते हैं। एक ही बीज पर फिर से चलाए गए गेम को XRPL मेमो के लिए अलग `run_id` मिलते हैं। GitHub रिलीज़ / `npx` बाइनरी अब `xrpl-py` को बंडल करते हैं। विंडोज पाइप आउटपुट (`cp1252`) अब Rich बॉक्स-ड्राइंग वर्णों पर क्रैश नहीं होता है (#19)।

**1.3.0** — चार अंत जिन्हें आप वास्तव में प्राप्त कर सकते हैं, जिसमें अनुभवी भी शामिल है। गाड़ी एक खतरा है, पूरा गेम नहीं। शुरुआती सर्दी एक चिह्नित वर्ष को धीमा कर देती है। रेगिस्तान में उथले पानी के रास्ते रेत से दूर रहते हैं। शिकार के नाम उन लोगों को बताते हैं जिन्हें चोट लगी है। `npx @mcptoolshop/escape-the-valley` v1.3.0 बाइनरी लॉन्च करता है (यह मृत v1.1.1 GitHub कलाकृति पर अटका हुआ था)।

**1.2.1** — PyPI व्हील वास्तव में अपलोड करता है (मेटाडेटा-संस्करण 2.3)। 1.2.0 के समान उत्पाद।

**1.2.0** — GitHub रिलीज़ बाइनरी लॉन्च (इवेंट लाइब्रेरी + स्टाइलशीट बंडल; स्मोक `--help` और ≥200 घटनाओं की पुष्टि करता है)। `trail ledger proof` लोड किए गए सेव की जाँच करता है। टीयूआई बीज/सिद्धांत/मोड़/मनोबल दिखाता है; `c` गति को चक्रित करता है; लेजर मेनू `R` इस सेव को प्रमाणित करता है। एचयूडी 80×24 और 120×30 पर पठनीय है।

**1.1.1** — `pip install "escape-the-valley[voice]"` वास्तव में स्थापित होता है (अतिरिक्त ने एक अप्रकाशित पैकेज को पिन कर दिया था)। PyInstaller बाइनरी अब वॉयस एक्स्ट्रा को नहीं खींचता है।

**1.1.0** — स्ट्रीमिंग कथन, वर्गीकृत अंत, ऐसी घटनाएँ जो घाव कर सकती हैं, ऑन-लेजर समाधान प्रमाण, गेम कलाकृतियाँ।

v1.1.0 और v1.1.1 GitHub रिलीज़ से जुड़े बाइनरी लॉन्च नहीं होते हैं (जमे हुए एंट्रीपॉइंट में एक सापेक्ष आयात)। `pip install escape-the-valley` या v1.2.0+ GitHub बाइनरी / `npx` लॉन्चर का उपयोग करें।

## त्वरित शुरुआत

```bash
pip install escape-the-valley

# Zero-prerequisite npm launcher (GitHub v1.3.3 binary; v1.1.0 and v1.1.1
# artifacts do not start):
#   npx @mcptoolshop/escape-the-valley tui --seed 42

# Launch the full-screen TUI (recommended)
trail tui --seed 42

# Resume a saved game
trail tui --continue

# Spoken voice (opt-in; needs pip install "escape-the-valley[voice]").
# AI narration is already on by default when Ollama is running;
# pass --gm-off to disable the GM. --voice does not turn the GM on.
trail tui --seed 42 --voice

# With voice pacing control
trail tui --seed 42 --voice --voice-pace slow

# Without AI narration (deterministic mode; same seed and choices give the same run in this version)
trail tui --seed 42 --gm-off

# Use a specific Ollama model
trail tui --seed 42 --model mistral
```

## कैसे खेलें

प्रत्येक टर्न में आप शिविर से एक क्रिया चुनते हैं:

| क्रिया | यह क्या करता है |
|--------|-------------|
| **Travel** | घाटी के निकास की ओर बढ़ें। भोजन और पानी की लागत। टूटने और घटनाओं का जोखिम। |
| **Rest** | दल को ठीक करें, मनोबल को बहाल करें। आपूर्ति की लागत लेकिन कोई प्रगति नहीं। |
| **Hunt** | भोजन के लिए एक मौका के लिए गोला-बारूद खर्च करें। जंगलों और मैदानों में बेहतर। |
| **Repair** | गाड़ी को ठीक करने के लिए एक अतिरिक्त भाग खर्च करें। जीवित रहने के लिए महत्वपूर्ण। |

**घटनाएँ** यात्रा को विकल्पों (ए/बी/सी) के साथ बाधित करती हैं। सतर्क विकल्प सुरक्षित होते हैं लेकिन समय की लागत आती है। साहसी विकल्प तेज़ होते हैं लेकिन जोखिम भरे होते हैं। कोई हमेशा सही उत्तर नहीं होता है।

**गाड़ी सब कुछ है।** यदि इसमें कोई भाग नहीं है और यह टूट जाती है, तो गेम समाप्त हो जाता है। इसे आधे से अधिक स्थिति में रखें और अस्थायी टूटने के प्रतिरोध के लिए रखरखाव विंडो (आराम करें फिर मरम्मत करें) करें।

**गति** गति बनाम सुरक्षा को नियंत्रित करती है। स्थिर डिफ़ॉल्ट है। तेज़ गति अधिक दूरी तय करती है लेकिन अधिक आपूर्ति जलाती है और गाड़ियाँ तेजी से टूट जाती हैं।

**एस्केप वाल्व** (कठिन राशन, हताश मरम्मत, कार्गो छोड़ना) आपात स्थिति के लिए मौजूद हैं। इनके दुष्प्रभाव और कूलडाउन होते हैं - अंतिम उपाय, रणनीतियाँ नहीं।

अधिक गहन सुझावों के लिए, [सर्वाइवल गाइड](https://mcp-tool-shop-org.github.io/escape-the-valley/handbook/survival-guide/) देखें।

## जीएम प्रोफाइल

एआई कथनकर्ता यांत्रिकी को नहीं, बल्कि स्वर को आकार देता है। तीनों प्रोफाइल एक ही गेम खेलते हैं।

- **Chronicler** — जमीनी, व्यावहारिक, सरल। न्यूनतम लोककथाएँ। बताता है कि क्या हुआ।
- **Fireside** — गंभीर अलाव कथनकर्ता। सूक्ष्म अवास्तविक क्षण। डिफ़ॉल्ट।
- **Lantern-Bearer** — अवास्तविक और सीमांत, लेकिन फिर भी परिणामों में निहित। अजीब।

`--gm-profile` के साथ सेट करें: `trail tui --gm-profile lantern`

## आपूर्ति

गेम दो श्रेणियों में 12 प्रकार के संसाधनों को ट्रैक करता है:

**खपत योग्य:** भोजन, पानी, जलाऊ लकड़ी, दवा, नमक, गोला-बारूद, लालटेन का तेल, कपड़ा

**उपकरण:** भाग, रस्सी, उपकरण, जूते

5 मुख्य आपूर्ति (भोजन, पानी, दवा, गोला-बारूद, भाग) सबसे महत्वपूर्ण हैं। विस्तारित आपूर्ति जैसे जलाऊ लकड़ी, नमक, लालटेन का तेल और कपड़ा गहराई जोड़ते हैं: जलाऊ लकड़ी रात के शिविरों को ईंधन देती है, नमक भोजन को खराब होने से बचाता है, लालटेन का तेल रात में सुरक्षित यात्रा को सक्षम बनाता है, और कपड़ा उपकरणों और गाड़ी के कवर को पैच करता है।

## Ledger Backpack (वैकल्पिक)

Ledger Backpack आपके 5 मुख्य आपूर्ति (भोजन, पानी, दवा, गोला-बारूद, भाग) को XRPL Testnet पर टोकन के रूप में ट्रैक करता है। प्रत्येक शहर के चेकपॉइंट पर एक समझौता रसीद ऑन-चेन पर दर्ज की जाती है। आपके गेम के अंत में, आपके trail लेजर में लेनदेन आईडी शामिल हैं जिन्हें कोई भी सत्यापित कर सकता है।

पूरी तरह से वैकल्पिक। इसे बंद करने पर गेम बिल्कुल वैसे ही चलेगा (यह डिफ़ॉल्ट सेटिंग है)। इसे TUI में L मेनू से या CLI के माध्यम से सक्षम करें:

```bash
trail ledger enable
trail ledger status
trail ledger reconcile  # retry failed settlements
trail ledger proof      # PASS / FAIL / INCONCLUSIVE on this save
```

TUI में, **L** लेज़र मेनू खोलता है; बैकपैक चालू होने पर, **R** इस सेव की पुष्टि करता है (समान परिणाम)। यह रेस्ट नहीं करता।

`npx` / GitHub रिलीज़ बाइनरी में शामिल; `pip` इंस्टॉलेशन के लिए, `xrpl-py` निर्भरता के लिए `pip install "escape-the-valley[xrpl]"` (या `pip install -e ".[xrpl]"`) चलाएं।

| `trail parcel list` | प्राप्त पार्सल की सूची बनाएं |
| `trail parcel accept <id>` | लंबित पार्सल स्वीकार करें |
| `trail parcel sent` | आपके द्वारा भेजे गए पार्सल की सूची बनाएं |
| `trail wallet share` | ट्रेडिंग के लिए अपना वॉलेट पता प्रिंट करें |

## चेतावनी संकेत

डिफ़ॉल्ट रूप से, गेम नए खिलाड़ियों को जल्दी खतरे का पता लगाने में मदद करने के लिए विस्तृत चेतावनियाँ दिखाता है। अनुभवी खिलाड़ी न्यूनतम मोड पर स्विच कर सकते हैं, जो केवल अंतिम-क्षण, गंभीर खतरों की चेतावनियाँ दिखाता है:

```bash
trail tui --callouts minimal
trail new --callouts minimal
```

## समस्या निवारण

**यदि कुछ गलत लगता है, तो पहले `trail self-check` चलाएं।** यह रिपोर्ट करता है कि क्या Ollama पहुंच योग्य है, क्या आपका सेव लोड होता है, और कौन सा मॉडल स्थापित है। तीन चीजें जो गलत हो सकती हैं:

| लक्षण | कारण | समाधान |
|---------|-------|-----|
| **Generic / no narration** | Ollama नहीं चल रहा है (GM वैकल्पिक है और वापस चला जाता है, कभी भी खराब नहीं होता) | Ollama (`ollama serve`) शुरू करें, या `--gm-off` के साथ नियतात्मक रूप से खेलें। पुष्टि करने के लिए `trail self-check` चलाएं। |
| **लेज़र लंबित / सेटलमेंट विफल** | XRPL Testnet एक सार्वजनिक परीक्षण नेटवर्क है और कभी-कभी अस्थिर होता है | `trail ledger reconcile` विफल सेटलमेंट को फिर से प्रयास करता है; जब नेटवर्क ठीक हो जाए तो इसे फिर से चलाएं। किसी भी तरह से आपूर्ति स्थानीय रूप से सही है। |
| **Save won't resume** | `run.json` लेखन के दौरान छोटा या दूषित हो गया | इंजन इसे `run.json.corrupt-<timestamp>` के रूप में क्वारंटाइन करता है इससे पहले कि इसे अस्वीकार कर दिया जाए, इसलिए आपकी अगली सेव साक्ष्य को नष्ट नहीं कर सकती। उस बैकअप से पुनर्प्राप्त करें, या एक नए सीड से एक नया रन शुरू करें। |

पहला वर्णित टर्न मॉडल लोड करता है और इसमें 10-30 सेकंड लग सकते हैं - यह सामान्य है, यह कोई रुकावट नहीं है। पूरी जानकारी: [समस्या निवारण पुस्तिका](https://mcp-tool-shop-org.github.io/escape-the-valley/handbook/troubleshooting/)।
